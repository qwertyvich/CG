# Тренировка перед защитой

Сначала найдите ответ в коде по [CODE_MAP](CODE_MAP.md), затем объясните без чтения. При тренировке в чате — один вопрос за раз: дождаться ответа, проверить смысл, только потом переходить дальше.

## Короткие вопросы

| Вопрос | Точный короткий ответ |
| --- | --- |
| Что делает нормаль? | Задаёт направление поверхности; dot с направлением света определяет освещённость. |
| Почему 202 вершины, хотя цилиндр тот же? | Боковина и крышки имеют одинаковые позиции на ребре, но разные нормали; записи атрибутов разделены. |
| Почему inverse-transpose? | Сохраняет ортогональность нормали касательным при неравномерном масштабе. Для TRS у нас это R*S⁻¹. |
| Где находится камера? | Camera.position в мире; V — обратная CameraWorld, она меняет координаты наблюдения. |
| Почему обратный порядок вращений? | (ABC)⁻¹=C⁻¹B⁻¹A⁻¹. Для T*Rz*Ry*Rx получается Rx⁻¹*Ry⁻¹*Rz⁻¹*T⁻¹. |
| Что такое FOV? | Вертикальный угол обзора перспективной камеры; он не заменяет позицию камеры. |
| Что такое N/L/V/H? | Нормаль; от фрагмента к свету; от фрагмента к камере; normalize(L+V). Всё в мировом пространстве. |
| Блинн–Фонг или Phong? | Здесь pow(N·H,shininess), а не reflect и угол отражённого луча с камерой. |
| Что делает shininess? | Меняет степень в зеркальном члене: больше степень — уже блик. Не меняет мощность лампы. |
| Почему NdotL>0 проверяется до блика? | Отвёрнутая от лампы поверхность не должна получать прямой зеркальный вклад. |
| Зачем safeNormalize? | Вектор камеры/лампы или L+V может быть почти нулевым; деление на ноль дало бы NaN. |
| Почему ambient один? | Это глобальный фон; иначе добавление ламп усиливало бы фон сцены. |
| Зачем два sets? | Общие ресурсы сцены отделены от model/material конкретного объекта, оба реально привязаны перед draw. |
| Что означает std140/std430? | Правила расположения данных в GPU-буферах; C++ offsets и array stride должны совпадать с GLSL. |
| Чем binding отличается от location? | Binding внутри descriptor set выбирает ресурс; location связывает vertex attribute или varying. |
| Почему нельзя пересылать bool? | У C++ и GLSL нет гарантии одинакового представления; отправляются uint flags или нулевая intensity. |
| Почему SSBO с lights[]? | Длина задаётся CPU-буфером и count; в GLSL нет фиксированного числа ламп. |
| Чем count отличается от capacity? | Count — записанные элементы списка, capacity — выделенное место. Shader читает только count. |
| Что при пустом списке? | Buffer остаётся размером минимум в одну запись, но count=0, цикл не выполняется. |
| Почему UI может редактировать Scene до fence? | Scene находится в CPU-памяти; GPU buffers записываются позже, после prepare. |
| Когда можно обновлять descriptor set? | После завершения его использования; в этом каркасе — после fence предыдущего кадра. |
| Зачем VMA flush? | Для видимости host-записей в noncoherent memory; наличие mapping не гарантирует coherent. |
| Почему у directional нет attenuation? | Он моделирует параллельные лучи удалённого источника, позиции в сцене нет. |
| Как доказать 1/r²? | При фиксированных N/L/V сравнить линейные вклады на r и 2r: отношение 1/4 вне epsilon-области. |
| Почему нельзя сравнить просто яркость двух скриншотов? | Меняются углы; sRGB и насыщение нелинейны относительно вычисленного светового вклада. |
| Куда направлен spot.direction? | От лампы в сцену; поэтому cosTheta=dot(-L,direction). |
| Почему cosInner≥cosOuter? | Косинус убывает на [0°,90°], а inner≤outer. |
| Что при inner=outer? | Hard step без smoothstep с равными аргументами; мягкой зоны нет. |
| Что при нулевом direction? | На CPU используется стабильный (0,-1,0), одинаковый для света и геометрии конуса. |
| Что делает unlit shader? | Выводит постоянный цвет с общей обработкой sRGB, не применяет материал и освещение. |
| Конус задаёт дальность света? | Нет, его длина только для показа; свет затухает по 1/r² без обрезания этой длиной. |
| Почему не нужны wideLines/fillModeNonSolid? | Конус — обычный line list шириной 1, а не wireframe-треугольники. |
| Как избежать двойной gamma-коррекции? | При sRGB attachment не кодировать в shader; при UNORM выполнить одно явное sRGB-кодирование. |
| Как обрабатывается minimize? | Нулевой extent не создаётся; кадр пропускается, rebuild выполняется после восстановления поверхности. |
| Что показала validation? | Итоговый smoke: 0 validation errors; отдельно 2 общих loader errors о старых Steam JSON, они сохранены. |

## Десять небольших упражнений

1. **Сузить блик.** В `controls.cpp::drawControls`, Model and material, изменить Shininess с 8 на 128. Предсказать сужение блика. Только UI; оставить один directional, убрать ambient/point/spot. Вернуть Reset scene.
2. **Убрать зеркальный цвет.** Обнулить Specular color или снять Specular contribution. Diffuse остаётся. Только UI; найти связь `buildUniforms → ModelGpu.specular → evaluateBlinnPhong`. Вернуть reset.
3. **Развернуть directional.** Изменить знак всех компонент Direction. Освещённая сторона меняется, расстояние не участвует. Только UI; найти минус перед scene.directionalDirection в shader. Вернуть reset.
4. **Отличить FOV от перемещения.** Изменить FOV 30→80, затем Camera Z. Найти `cameraView` и `perspective` в scene.cpp. Объяснить разницу, перейти в ортографию и найти её отдельный размер. Только UI; Reset camera.
5. **Проверить жёсткие нормали.** Найти четыре push_back на сегмент в `generateCylinder`, затем применить Scale (0.5,1.8,1.2) и Rotation Y=40. Назвать разные нормали крышек и R*S⁻¹. Только UI/чтение; Reset model.
6. **Проверить динамический SSBO.** Point lights: добавить 5 ламп, удалить первую/среднюю/последнюю через Remove, Clear и Add. Наблюдать count/capacity; объяснить, почему capacity не обязана уменьшаться. Только UI; найти `ensureStorage`. Вернуть reset.
7. **Свести углы.** В Spot lights поставить inner=outer=25°. Граница становится резкой, деления на ноль нет. Затем outer=35°, inner=15° — переход расширяется. Только UI; найти `spotFactor`. Вернуть reset.
8. **Предсказать отсутствие attenuation.** Найти `inverseSquare` в lab2.frag. Объяснить результат временного `return 1.0`: point/spot не слабеют с расстоянием. Для опыта сохранить копию shader, изменить, выполнить `cmake --build build-vs2022 --config Debug --target cg-lab2`, перезапустить; затем восстановить формулу и пересобрать. C++ пересобирать отдельно не нужно. Не оставлять итоговый shader изменённым.
9. **Скрыть помощников.** Снять оба Show. Цилиндр освещается как раньше. Затем обнулить ambient: видимые после возврата кубы сохранят цвет. Только UI; найти `drawMarkers`, unlit.frag и условие s.showCones. Вернуть reset.
10. **Найти безопасную точку обновления.** Показать путь `main → prepare → renderer::render → uploadScene → ensureStorage/writeBuffer`. Объяснить, что произойдёт при переносе upload в update до ожидания fence. Только чтение кода, такую поломку в проект не вносить.

После упражнений нажмите Reset scene. Если меняли исходники, верните изменения, пересоберите и повторите CPU-тест/smoke. После правки строк обновите карту командой `python tools/update_code_map.py`.
