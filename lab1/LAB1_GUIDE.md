# Лабораторная №1: цилиндр на Vulkan

Вариант 8: `((20 - 1) % 12) + 1 = 8`. Цилиндр с 50 сегментами окружности каждого основания. Выполнены базовый вариант и первые пять дополнительных заданий. Задание №6 с несколькими объектами не реализовано. Оценка зависит также от защиты и сроков сдачи.

## Сборка и запуск

Открой **x64 Native Tools Command Prompt for VS 2022** или **Developer Command Prompt for VS 2022**:

```bat
cd /d C:\Users\user\Desktop\CG\lab1
where cl
cmake --version
glslc --version
cmake --preset msvc-debug
cmake --build build-debug --config Debug --parallel
build-debug\Debug\vulkan-starter-app.exe
```

Нужны MSVC, Windows SDK, CMake, Git и Vulkan SDK. При первой конфигурации FetchContent скачивает GLFW, vk-bootstrap, VMA и ImGui. Шейдеры автоматически собираются через glslc. Генерируемые `.spv` вручную редактировать не нужно.

Запускай из `lab1`: пути `shaders/lab1.vert.spv` и `shaders/lab1.frag.spv` относительные. Для запуска из Visual Studio рабочий каталог задан в CMake. Консоль оставлена открытой для диагностики.

Если `cmake` отсутствует в PATH, открой новый Developer Command Prompt. В установленном здесь Build Tools он расположен в `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin`.

## Файлы и архитектура

Основа — [шаблон преподавателя](https://github.com/vladeemerr/vulkan-starter-app). `application.hpp`, `graphics_internal.hpp`, `main.cpp` и CMake presets сохранены.

| Файл | Изменение |
| --- | --- |
| `source/application.cpp` | Геометрия, матрицы, буферы VMA, pipeline, push constants, ImGui, анимация и команды рисования |
| `shaders/lab1.vert` | Преобразование позиции через MVP, передача цвета вершины |
| `shaders/lab1.frag` | Умножение интерполированного цвета вершины на tint |
| `CMakeLists.txt` | Компиляция шейдеров, обязательное наличие glslc, консоль, рабочий каталог отладчика |
| `source/graphics_internal.cpp` | Размер пула дескрипторов ImGui и зависимость первого render pass от получения swapchain image |
| `README.md`, `LAB1_GUIDE.md` | Навигация к инструкции, устройство решения и подготовка к защите |

`initialize()` один раз создаёт геометрию, vertex/index buffers и pipeline. При ошибке освобождает частично созданные ресурсы. `update(time)` обновляет анимацию и интерфейс. `render(fd)` пересчитывает MVP, записывает command buffer и рисует цилиндр. `shutdown()` ждёт graphics queue idle и освобождает созданные ресурсы. Shader modules уничтожаются сразу после создания pipeline.

В `render()` выполняются reset/begin command buffer, begin render pass с очисткой цвета и глубины, bind pipeline, viewport/scissor, vertex/index buffers, push constants, `vkCmdDrawIndexed`, end render pass, end command buffer. Существующий `submitAndPresent()` затем рисует ImGui и отправляет кадр.

Две локальные правки инфраструктуры понадобились при реальном запуске. ImGui 1.92 выделяет отдельные наборы для sampler и изображений шрифта: `maxSets` теперь равен сумме минимальных размеров этих пулов (2+8), а не числу изображений swapchain. Иначе загрузка шрифта завершалась assertion. Также добавлена внешняя subpass dependency с `COLOR_ATTACHMENT_OUTPUT` в source/destination stages: она связывает ожидание acquire semaphore с первым переходом layout swapchain image. Без неё synchronization validation сообщала WRITE_AFTER_READ. Флаги depth stages/access включены для depth attachment того же прохода.

## Геометрия и путь данных

Ось цилиндра — Y, радиус — 1, высота — 2. Для сегмента i угол равен `2*pi*i/50`, `x=cos(angle)`, `z=sin(angle)`. Вершины добавляются парами: нижняя `(x,-1,z)` и верхняя `(x,1,z)`, затем два центра оснований.

Всего **102 вершины, 200 треугольников, 600 индексов uint32_t**. Каждый сегмент даёт два боковых треугольника и по одному треугольнику каждой крышки. `(i+1)%50` замыкает шов. Все грани ориентированы наружу. Крышки образуют веера через индексы; topology всего pipeline — `TRIANGLE_LIST`. Culling отключён, видимость определяет depth test.

`Vertex` содержит position и color: по три float, всего 24 байта. В `createPipeline()` stride и offsets сопоставляют поля с `location=0` и `location=1` GLSL. Буферы создаются через VMA, отображаются в CPU, заполняются через memcpy и flush. Геометрия после инициализации неизменна.

Цвет вычисляется из локальной позиции: каждая координата нормируется из `[-1,1]` в `[0,1]`. Вершинный шейдер передаёт его растеризатору; цвет внутри треугольника интерполируется с перспективной коррекцией. Фрагментный шейдер выполняет покомпонентное умножение:

```glsl
outColor = vec4(proceduralColor, 1.0) * pushConstants.tintColor;
```

Белый tint сохраняет исходный цвет, чёрный даёт чёрный объект, красный оставляет красную компоненту. Это раскраска, освещения в работе нет. ColorEdit3 изменяет RGB; alpha остаётся 1, blending отключён.

## Матрицы и Vulkan

`Mat4` хранится по столбцам: элемент `(row,column)` имеет индекс `column*4+row`. GLSL использует ту же раскладку. Векторы — столбцы, преобразования применяются справа налево:

```text
Model = Translation * RotationZ * RotationY * RotationX * Scale
MVP   = Projection * View * Model
gl_Position = MVP * vec4(localPosition, 1)
```

Сначала масштабируем, затем вращаем вокруг X/Y/Z, затем переносим. Интерфейс показывает градусы, sin/cos получают радианы. Масштаб ограничен снизу 0.05 даже при ручном вводе нуля или отрицательного значения.

Камера находится в `(0,0,10)` и смотрит вдоль `-Z`. View — её обратное преобразование: `Translation(0,0,-10)`.

Perspective: FOV 50 градусов, near=0.1, far=100, clip w равен `-z_view`. После деления на w далёкие объекты выглядят меньше. Orthographic сохраняет размер с расстоянием; полувысота видимого объёма 4.65, полуширина — `4.65*aspect`.

Обе матрицы дают глубину Vulkan `[0,1]`. Коэффициент Y инвертирован для viewport положительной высоты. Aspect берётся из текущего swapchain в `render()` после `prepare()`, который мог выполнить resize. Pipeline не нужно пересоздавать при обычном изменении размера: viewport/scissor динамические.

Push constants содержат MVP (64 байта) и tint (16 байт), всего **80 байт**, что меньше гарантированных Vulkan 128 байт. `static_assert` проверяет размер и смещение tint=64. Range доступен vertex и fragment stages. `vkCmdPushConstants()` записывает параметры для текущего draw. Для цилиндра UBO и descriptor sets не создаются; собственные дескрипторы ImGui остаются в шаблоне.

## Анимация и управление

`t += deltaTime * animationSpeed`, где deltaTime — интервал времени GLFW между кадрами. Интервал ограничен `[0,0.1]` секунды, чтобы задержка при перемещении окна или отладке не давала большого скачка.

```text
x = manualX + radius*cos(t)
y = manualY + verticalAmplitude*sin(verticalFrequency*t)
z = manualZ + radius*sin(t)
rotationY = manualRotationY + accumulatedRotation
rotationX = manualRotationX + 0.55*accumulatedRotation
accumulatedRotation += deltaTime*animationSpeed*rotationSpeed
```

Фаза и угол хранятся как double. Фаза не сбрасывается на 2*pi, иначе дробная verticalFrequency давала бы разрыв. Для вычисления каждого угла вращения отдельно берётся остаток от 360 градусов. При Pause предыдущее время обновляется, фаза и угол стоят: Resume не включает время паузы. Ручные параметры сохраняются как центр траектории и добавочный поворот.

| Элемент | Переменная/действие |
| --- | --- |
| Perspective / Orthographic | Тип проекции |
| Position X/Y/Z | Центр траектории |
| Rotation X/Y/Z | Дополнительный поворот в градусах |
| Scale X/Y/Z | Локальный масштаб |
| Play | Накопление фазы и угла |
| Animation speed | Общий множитель скорости |
| Trajectory radius | Радиус в плоскости XZ |
| Vertical amplitude / frequency | Высота и частота колебаний Y |
| Rotation speed | Скорость вращения до общего множителя |
| Tint color | RGB множитель цвета |
| Reset | Исходные параметры и фаза |

Ctrl+click по числовому полю позволяет ввод с клавиатуры. Параметры меняют объект и на паузе. Большие перемещения и масштабы могут вывести фигуру из объёма камеры; Reset возвращает исходный вид.

## Вопросы к защите

1. **Зачем однородные координаты?** Они позволяют описать перенос и остальные аффинные операции матрицей 4×4. У точки w=1, у направления w=0. После проекции координаты делятся на w.
2. **Model, View, Projection?** Переводят локальные координаты в мировые, затем в систему камеры, затем в clip space.
3. **Почему важен порядок матриц?** Умножение некоммутативно. T*R сначала вращает вокруг локального начала, затем переносит; R*T может вращать перенесённый объект вокруг мирового начала.
4. **Перспектива и ортография?** В перспективе размер уменьшается с расстоянием, в ортографии сохраняется.
5. **Как триангулирован цилиндр?** 50 боковых участков по два треугольника плюс по 50 в каждой крышке.
6. **Зачем index buffer?** Общие вершины хранятся один раз: 102 записи вместо 600 полных вершин.
7. **Что делает vertex shader?** Вычисляет clip-позицию вершины и выдаёт атрибуты для интерполяции.
8. **Что делает fragment shader?** Вычисляет цвет фрагмента из интерполированных данных и tint; depth test определяет его видимость.
9. **Что такое SPIR-V?** Бинарное промежуточное представление шейдеров, которое glslc получает из GLSL, а драйвер использует при создании pipeline.
10. **Что такое descriptor set?** Набор привязок ресурсов, например буферов и изображений, к шейдерам. Для наших 80 байт достаточно push constants.
11. **Что меняется каждый кадр?** Фаза, угол, значения интерфейса, MVP и push constants. Геометрия постоянна.
12. **Зачем deltaTime?** Позволяет задавать скорость в единицах в секунду независимо от FPS обычных кадров.
13. **Как интерполируются цвета?** По барицентрическим координатам с перспективной коррекцией.
14. **Зачем умножение цветов?** Tint масштабирует RGB-компоненты, сохраняя вариацию процедурной раскраски.
15. **Зачем depth buffer?** Хранит глубину ближайшего прошедшего фрагмента; LESS пропускает более близкие, clear=1 задаёт дальнюю границу.
16. **Как ImGui влияет на фигуру?** Меняет параметры CPU, по которым пересчитываются матрицы и tint; интерфейс рисуется отдельным pipeline шаблона.
17. **Почему Resume не прыгает?** Время предыдущего кадра обновляется и на паузе, поэтому время паузы не интегрируется.
18. **Как освобождаются ресурсы?** После queue idle: vkDestroyPipeline/Layout и vmaDestroyBuffer; модули шейдеров удалены после создания pipeline.

## Ручная проверка перед защитой

- Переключить обе проекции и изменить размер окна; пропорции цилиндра должны сохраняться.
- На паузе проверить Position, Rotation и Scale по каждой оси; вручную ввести масштаб 0, убедиться в ограничении 0.05.
- Включить Play, менять скорость, радиус, амплитуду, дробную частоту и вращение; наблюдать дольше одного оборота.
- Поставить Pause, подождать, продолжить; скачка накопленной фазы быть не должно.
- Проверить белый, красный и произвольный tint. Градиент должен сохраняться; чёрный tint закономерно даёт чёрную фигуру.
- Поворотами осмотреть обе крышки и перекрытие ближних/дальних поверхностей.
- Нажать Reset, штатно закрыть окно и проверить консоль на сообщения Vulkan validation, включая освобождение ресурсов.

## Выполненные проверки

Сборка Debug выполнена MSVC 19.44 / VS 2022, оба шейдера проверены `spirv-val`. CPU-проверка подтвердила 102 вершины, 200 невырожденных граней с ориентацией наружу, замкнутость всех 300 рёбер, объём, цвета, порядок матриц и границы глубины обеих проекций.

Проверка на Vulkan включала обе проекции, все XYZ-преобразования, ограничение нулевого/отрицательного масштаба, смену tint, Pause/Resume с моделированием 20 секунд паузы, дробную verticalFrequency=1.37 и вращение дольше 360 градусов. Проверены resize 1600×900, 900×900, 700×1000, 1280×720 и штатное освобождение ресурсов. В видимом окне проверены переключатель проекции и Pause: два снимка на паузе совпали побайтово.

В итоговом запуске с Khronos validation и synchronization validation нет validation errors/warnings. Есть информационное сообщение об активном слое. Во время resize шаблон может вывести `Swapchain is suboptimal for rendering!`: это уведомление о пересоздании swapchain, после которого работа продолжается. Первое конфигурирование VS generator также сообщает, что CMAKE_BUILD_TYPE из исходного preset не используется; для него конфигурацию задаёт `--config Debug`.
