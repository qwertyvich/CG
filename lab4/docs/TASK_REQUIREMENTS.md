## Этап 3 Depth-текстуры и compare samplers

Простая архитектура: отдельная 2D shadow map для солнца и отдельная 2D shadow map для выбранного прожектора. Atlas/cubemap не нужны.

- Выбери depth-формат через vkGetPhysicalDeviceFormatProperties/подходящий запрос: он должен поддерживать DEPTH_STENCIL_ATTACHMENT и SAMPLED_IMAGE для optimal tiling. Предпочтителен подходящий depth-only формат, например D32_SFLOAT или D16_UNORM, с проверкой поддержки. Не предполагай поддержку D24_S8, не копируй слепо формат экранного depth, который мог не проверяться на sampling.
- VkImage: отдельные размеры карты, optimal tiling, DEVICE_LOCAL, usage DEPTH_STENCIL_ATTACHMENT|SAMPLED, один mip для базовой реализации. Depth-aspect view. Начальное разрешение, например 1024 или 2048, с учётом maxImageDimension2D и памяти.
- Create VkSampler отдельно от обычных albedo samplers: compareEnable=VK_TRUE, compareOp=VK_COMPARE_OP_LESS. В shader с ним связан sampler2DShadow через корректный combined image sampler descriptor.
- Фильтрация по умолчанию NEAREST допустима и не требует PCF. LINEAR/hardware comparison filtering используй только при проверенной поддержке нужного формата/функциональности. PCF не является обязательным допзаданием PDF; можно добавить небольшой переключаемый фильтр после полного выполнения базы и spot-тени.
- Address mode/границы выбери явно. Для CLAMP_TO_BORDER укажи понятный светлый depth border, но всё равно обрабатывай выход shadow coordinates за допустимую область. Border state не исправляет неверные light matrices.
- STORE_OP_STORE сохраняет depth для последующего sampling; LOAD_OP_CLEAR очищает глубину, обычно в 1.0 при обычной нереверсной глубине. Поддержи корректный переход первого кадра и следующих кадров.
- При отключённых тенях sampler descriptors всё равно должны быть валидны, либо shader гарантированно не должен их использовать по корректной схеме. Не полагайся на неподдержанные null descriptors.
- Изменение resolution в UI необязательно. Если добавлено, безопасно пересоздавай maps/views/дескрипторы после завершения их использования; не пересоздавай всё каждый кадр без причины.

## Этап 4 Depth-only pipeline и проход Dynamic Rendering

- Создай отдельный graphics pipeline без цветовых attachments и без fragment shader: единственная shader stage — vertex. Укажи renderPass=VK_NULL_HANDLE и VkPipelineRenderingCreateInfo (core/KHR по выбранному пути) с depthAttachmentFormat выбранной карты, colorAttachmentCount=0. Согласуй stencilAttachmentFormat с реальным использованием; если stencil не используется — UNDEFINED.
- Vertex shader вычисляет gl_Position = lightViewProjection * model * vec4(position,1). Он не рассчитывает albedo/освещение и не пишет color. Привязывай реальную model запись через dynamic offset для КАЖДОГО объекта, как в главном проходе.
- Light VP передавай через согласованную структуру/descriptor либо небольшой vertex push block для shadow pass. Не ломай существующий fragment push block sampling-эффекта и совместимость pipeline layouts. Всегда записывай требуемые параметры перед соответствующим draw.
- Depth test/write включены. Rasterizer discard выключен. Для начала используй culling, который не теряет пол и нужные поверхности; не скрывай ошибку bias агрессивным отсечением лиц. Viewport/scissor равны shadow map, а не swapchain.
- До основного render pass: переход карты в depth attachment layout; VkRenderingAttachmentInfo для depth с imageView/layout/load/store/clear; VkRenderingInfo без color attachments; vkCmdBeginRendering(core/KHR); bind shadow pipeline; depth bias state; draw всех нужных caster/receiver meshes с актуальными матрицами; vkCmdEndRendering; переход карты в depth read-only/shader-read layout для sampling.
- Shadow pass не должен создавать VkRenderPass/VkFramebuffer и не должен вызывать vkCmdBeginRenderPass. Одного названия «dynamic» в функции недостаточно: проверь реальные команды и pipeline creation.
- Генерируй карту каждого активного источника с включённой тенью каждый кадр. Пауза анимации не должна превращать это в одноразовую заранее записанную/предвычисленную карту.
- После offscreen passes восстанови main viewport/scissor по swapchain, нужный pipeline/sets/vertex/index bindings, push constants sampling-эффекта и прочее состояние. Shadow state не должен случайно влиять на основной проход.

## Этап 5 Солнце Orthographic и LookAt База

- Directional direction в ЛР2/ЛР3 задавал направление движения лучей. Используй то же направление для shadow-camera: eye = target - normalize(direction)*distance, взгляд на target. Расстояние виртуальной камеры выбирается для покрытия сцены и near/far, а не для изменения интенсивности directional.
- Реализуй корректную LookAt-матрицу в принятом соглашении матриц/векторов. Target, up и direction должны давать устойчивый ортонормальный базис. При направлении, почти параллельном up, выбери другой опорный вектор; при нулевом направлении используй понятный fallback или сохрани последнее валидное. Не допускай NaN.
- LightVP = orthographic * lookAt. Ортографическая область должна покрывать пол и цилиндры, включая ожидаемое движение. Near/far корректные, near<far. Зафиксируй и объясни выбранные соглашения знаков/глубины.
- В ImGui добавь покрытие ортографической проекции: например Shadow half width / half height либо единый half extent с пояснением единиц, center/target при необходимости. Укажи, полные это размеры или половины. Это обязательный параметр из PDF.
- Изменение направления солнца, положения/масштаба/вращения цилиндров и анимации меняет их настоящую тень. Перемещение камеры наблюдателя не должно само по себе перемещать тень относительно мира.

## Этап 6 Sampling и корректное затенение

В main lit fragment shader добавь отдельные sampler2DShadow для солнца и spot-карты или эквивалентные явно документированные привязки. Используй реальное comparison sampling, а не sampler2D с ручным сравнением вместо требования PDF.

1. Из worldPosition получи lightClip = lightVP * vec4(worldPosition,1).
2. Для перспективного прожектора проверь w>0; выполни перспективное деление xyz/w. Для ортографии всё равно сохраняй понятный общий путь.
3. В Vulkan NDC depth уже [0,1]. Переводи только XY из [-1,1] в [0,1], не применяй OpenGL-преобразование z*0.5+0.5. Согласуй Y с light projection/viewport; не переворачивай Y дважды.
4. Проверь UV и depth на допустимый диапазон до выборки; для точек вне карты задай явное поведение «нет данных тени / visibility=1», не растягивай край карты на весь мир. Для spot освещение вне конуса дополнительно обнуляет существующий spot factor.
5. Comparison sampling вида texture(shadowSampler,vec3(uv,referenceDepth)) возвращает visibility. При LESS успех означает referenceDepth < sampledDepth. Зафиксируй семантику: 1 — свет виден, 0 — затенён, промежуточное — только если реально используешь фильтрацию. Не перепутай shadow amount и visibility.
6. Умножай visibility солнца только на diffuse+specular ЭТОГО directional light. Spot visibility влияет только на вклад выбранного прожектора. Остальные point/spot должны оставаться самостоятельными.
7. Ambient добавляется один раз и не умножается на visibility прямых источников. Emissive из ЛР3 прибавляется независимо и не исчезает в тени. Сохрани specular masks, albedo и sampling effect в обоих вариантах fragment pipeline.

## Этап 7 Depth bias и артефакты

## Этап 9 Синхронизация, ресурсы, совместимость

- Dynamic Rendering не выполняет автоматически все image layout transitions и зависимости за приложение. Явно синхронизируй depth writes (EARLY/LATE_FRAGMENT_TESTS и соответствующие access) с последующим shader sampled read (FRAGMENT_SHADER), затем следующий shader read с новыми depth writes при повторном использовании. Учитывай первое состояние UNDEFINED отдельно. Layout в descriptor должен совпадать с состоянием при sampling.
- Существующий main pass/ImGui и acquire/present сохраняют корректную синхронизацию. Не начинай nested rendering, shadow passes идут вне активного main render pass.
- В ранее изученной версии один кадр в работе, fence ожидался в prepare(). Обновляй GPU uniform/SSBO, light matrices, dynamic model slots и descriptors только после завершения предыдущего использования. Сначала осмотри актуальный порядок вызовов.
- При нескольких frames in flight нужны безопасные per-frame ресурсы либо области и синхронизация; не используй один shadow image конкурентно без защиты.
- Любое перевыделение maps/buffers, удаление spot, изменение размеров ресурсов и очистка выполняются с корректным lifetime. Старые image/view/sampler не уничтожаются, пока ими пользуется GPU или активный descriptor.
- Сохрани рабочие проверки Vulkan и synchronization validation; не отключай их для «успеха». Не выдавай сообщения loader стороннего Steam overlay за исправленную ошибку алгоритма. Логи доступны пользователю.
- Перед shutdown дождись GPU и освободи собственные resources в правильном порядке. Частичная неудача initialize тоже освобождает уже созданное и даёт понятный текст ошибки.
